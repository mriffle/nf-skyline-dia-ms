# Correctness Audit: nf-skyline-dia-ms

**Date:** 2026-04-14
**Branch audited:** `pdc-batches` (commit `d159ac2`)
**Scope:** Full workflow correctness — input resolution, search engines, Carafe, Skyline/QC/packaging/upload, main.nf orchestration, schema/config.
**Method:** Five parallel explorations by subsystem, followed by direct re-verification of the highest-impact findings against the source.

Totals: **5 critical**, **7 moderate**, **5 minor**, 5 false positives rejected during verification.

**Later additions:** issues found during real-run testing on 2026-11-26 are in the
[addendum](#addendum-2026-11-26-issues-found-during-real-run-testing) at the end of this file,
with the state of the fixes that came out of that work.

---

## Critical (workflow-breaking or silently corrupts artifacts)

### C1. `proteowizard_version` and `dia_qc_version` are never captured from Skyline — **FIXED 2026-08-28**

**Resolution:** `main.nf` now reads both back from `skyline.out` after the `skyline` call. Note
the impact was wider than the two variables: `Channel.concat` silently dropped every argument
after the first null one, so `carafe_version` was missing from the run details too.

**File:** `main.nf:67-68`, `main.nf:242-246`

Both are declared `null` at lines 67-68 and never reassigned. The Skyline workflow emits them (`workflows/skyline.nf:105,110`) but `main.nf` never does `proteowizard_version = skyline.out.proteowizard_version`. At line 242 they are passed into `search_engine_version.concat(proteowizard_version, dia_qc_version, carafe_version)` as raw nulls. `carafe_version` is reassigned in the same file (lines 201/205/208), so the omission is specifically for the Skyline-emitted versions.

**Outcome:** `nextflow_run_details.txt` is missing Skyline/msconvert/DIA-QC version metadata, and the concat may NPE depending on Nextflow's null tolerance.

**Fix sketch:** After the `skyline(...)` call (~`main.nf:240`), add `proteowizard_version = skyline.out.proteowizard_version` and `dia_qc_version = skyline.out.dia_qc_version`.

---

### C2. Minimize enabled ⇒ batch-document join fails — **FIXED 2026-08-28**
**File:** `workflows/skyline.nf:49`, `modules/skyline.nf:245`

**Resolution:** the regex now also strips `_minimized`, and
`test-resources/test-diann-minimize.config` (in the CI matrix) exercises the
minimize + annotate + multi-batch combination.

**Follow-up:** the regex was still wrong for a document or batch name ending in `_`, or in
`_annotated` / `_minimized` when that step did not run. The join no longer parses file names;
it matches on the file name predicted by `get_final_skyline_doc_name`
(`subworkflows/skyline_import.nf`).

Regex `/(_annotated)?\.sky$/` only strips `_annotated.sky` or `.sky`. After minimize, filenames become `{doc_name}[_batch]_minimized.sky.zip` or `{doc_name}[_batch]_annotated_minimized.sky.zip`. `baseName.replaceAll(...)` leaves `_minimized` (or `_annotated_minimized`) dangling. The expected key (line 48) is `{doc_name}[_batch]`, so the `.join(..., failOnMismatch: true)` on line 49 must fail.

**Outcome:** Any run with `skyline.minimize = true` breaks at batch-document assembly — QC, reports, hashes, and uploads all fail. No stub config exercises this combination, so CI does not catch it.

**Fix sketch:** Extend the regex to also strip `_minimized` before/after `_annotated`: `/(_annotated)?(_minimized)?\.sky$/` (or centralize via the `sky_basename` helper in `modules/skyline.nf:4-6`).

### C3. `skyline.fasta` Panorama auth check uses wrong parameter
**File:** `subworkflows/get_input_files.nf:29`

Line 29 reads `if(panorama_auth_required_for_url(params.fasta))` but the block downloads `params.skyline.fasta`. Three audit agents independently flagged this.

**Trigger:** `params.skyline.fasta` is a private Panorama URL and `params.fasta` is local (or vice versa).

**Outcome:** Either `file(params.skyline.fasta, checkIfExists: true)` fails on a URL at line 33, or `PANORAMA_GET_FASTA` is called with a local path at line 30. The auth-trigger coverage in `main.nf:336` is already correct — only the download-site decision is inverted.

**Fix sketch:** Change `params.fasta` to `params.skyline.fasta` on line 29.

---

### C4. Duplicate `exclude_projects` guard — `exclude_replicates` never gates normalization
**File:** `subworkflows/generate_qc_report.nf:13-14`

`run_impute_normalize()` checks `exclude_projects != null` twice. Line 14 was clearly intended to be `exclude_replicates`. Because `normalization_method` defaults to `'median'`, the default path still runs, so this is latent, but any user who explicitly sets `normalization_method = null` plus `exclude_replicates` will silently skip the filter/impute/normalize step.

**Fix sketch:** Change the second `params.qc_report.exclude_projects` to `params.qc_report.exclude_replicates`.

---

### C5. EncyclopeDIA + Carafe is unusable when no `params.spectral_library` is set
**Files:** `subworkflows/encyclopedia/main.nf:15-17`, `main.nf:195-200`

EncyclopeDIA validates `params.spectral_library` directly rather than the incoming channel. Carafe writes the library via `main.nf:200` as a channel override, but the param remains null. SPECIFICATION.md calls this out as a "quirk"; in practice it makes the combination invalid unless the user *also* supplies a dummy `params.spectral_library`.

**Decision required:** Either (a) reject the combination early in `main.nf`, or (b) change the EncyclopeDIA guard at lines 15-17 to test the channel contents instead of the param.

## Moderate (dropped artifacts, degraded behavior, confusing errors)

### M1. Final EncyclopeDIA combined `.elib` not included in `search_file_stats`
**Files:** `subworkflows/encyclopedia/main.nf:80,82`, `modules/encyclopedia.nf` (`ENCYCLOPEDIA_CREATE_ELIB`)

`output_file_stats` is sourced from per-file search stats only; the combined final elib is published but its md5/size never reach the checksum manifest or Panorama upload. Spec flags this gap (SPECIFICATION.md line 539) but the code has not been updated.

---

### M2. Final Cascadia `.blib` not included in `search_file_stats`
**File:** `subworkflows/cascadia/main.nf:45` (BLIB_BUILD_LIBRARY step)

Same pattern as M1: only per-file SSL hashes are emitted; the final blib is not. Spec flags this.

---

### M3. PDC batch-file parsing can crash on blank / truncated lines
**Files:** `subworkflows/get_pdc_files.nf:41-47`, `main.nf:358`

Both locations do `line.split('\t')[batch_idx]` with no bounds check. Groovy's split drops trailing empty fields, so a blank trailing line (common on hand-edited TSVs) causes `IndexOutOfBoundsException` when `batch_idx > 0`. Additionally, `if (fname && batch)` at line 45 silently skips rows with a blank batch column — the downstream "missing from batch file" error (line 89) then fires for that file, giving a misleading diagnosis.

**Fix sketch:** Skip blank lines before splitting; validate row length explicitly and error cleanly on short rows.

---

### M4. Carafe local-only inputs are not in the AWS auth trigger
**File:** `main.nf:332-344`

`is_panorama_authentication_required()` omits `carafe.peptide_results_file`, `carafe.carafe_fasta`, `carafe.diann_fasta`. The Carafe internals do accept Panorama URLs via `get_input_file`, so on AWS with any of these set to a private URL, the AWS secret is never built and the download fails at runtime.

**Decision required:** Either add these to the auth trigger, or reject Panorama URLs for these inputs at parameter-validation time.

---

### M5. Empty-string `pdc.batch_file` bypasses the `!= null` check
**File:** `main.nf:97,104`

`params.pdc.batch_file != null` passes for `""`, setting `use_batch_mode = true`, then `get_pdc_batch_names("")` calls `file("", checkIfExists:true)` for an unhelpful runtime error.

**Fix sketch:** Check for non-null **and** non-empty, or tighten the schema to reject empty strings.

---

### M6. Default Skyline template URL — staging not verified
**File:** `subworkflows/get_input_files.nf:58`

`file(params.default_skyline_template_file)` is passed a raw GitHub URL. Nextflow's `file()` does stage HTTP(S) URLs, so this works in practice, but there is no handling for network failure or cache misses. Flag for runtime verification rather than immediate fix.

---

### M7. DIA-NN silently accepts arbitrary-format spectral libraries
**File:** `subworkflows/diann/main.nf:58-60`

The conversion branch handles `.blib` and `.dlib`; anything else passes through unchanged. A user-supplied `.tsv`, `.speclib`, or other format is handed to DIA-NN as-is with no validation. If the file is not DIA-NN-compatible, the failure is deep inside DIA-NN rather than at input validation.

**Fix sketch:** Validate the library extension against a known-good list and either pre-convert or error at input time.

`params.search_engine.toLowerCase()` without `.trim()` means `"diann "` with trailing space falls through to the EncyclopeDIA format branch. The upstream normalization at `main.nf:71` already handles this for the dispatch, but Carafe re-reads the raw param.

## False positives rejected during verification

These were raised by audit agents but disproved by direct reading:

- **"PDC branch does not emit `file_json`, breaking metadata validation"** — PDC bypasses `get_replicate_metadata` entirely and uses PDC annotations directly (`main.nf:177-189`). No validation gap.
- **"`save_run_details` is called in two branches"** — Only one branch runs per execution (`msconvert_only` `return` at `main.nf:171`); not a duplication risk.
- **"Deprecated Skyline params silently diverge"** — `check_old_param_name()` rewrites `params.skyline.*` atomically at `main.nf:45-52` before any downstream read. No divergence.
- **"Replicate metadata Panorama Public miswired"** — The spec's "miswired" note is stale; current code routes private vs public correctly.
- **"Normalization guard fails when `exclude_replicates` is set alone"** — Real, but upstream defaults make it latent. Reclassified above as C4, not rejected outright.

## Not covered by this audit (worth a follow-up)

- **Interaction of `use_vendor_raw` with each search engine** — Cascadia expects mzML; if `use_vendor_raw` is set with Cascadia the upstream resolver leaves RAW/`.d` as-is, and there is no explicit guard. DIA-NN handles vendor RAW; EncyclopeDIA semantics unclear. **Still open as of 2026-09-02**, though partially narrowed: `use_vendor_raw` is now rejected at startup when combined with `msconvert.do_demultiplex` or with `msconvert_only`. The per-engine question is untouched — `get_ms_files` skips msconvert for *every* engine, not just DIA-NN. Note the config GUI models this the other way around (`computeWorkflowGraph.ts` `streamNeedsMsconvert` assumes msconvert still runs for non-DIA-NN engines, and its `vendor-raw-engine` rule is only a warning), so whichever way this is resolved is a two-repo change.
- **Concurrent-batch correctness** — DIA-NN batch support was not stressed for cross-batch contamination (shared stage-in paths, duplicate batch names, batch-name collisions with reserved strings).
- **Panorama upload ordering when `panorama.import_skyline=true`** — agents checked the guard exists but did not trace the actual ordering enforcement.
- **Process caching directives** — Carafe lacks `storeDir`; in long runs this may redo large work unnecessarily.
- **Schema vs. code drift audit at scale** — agents spot-checked; a full param-by-param comparison of `nextflow_schema.json` against every reference in `main.nf`/workflows/subworkflows was not performed.

## Addendum 2026-11-26: issues found during real-run testing

Found while diagnosing four real-run failures with real (non-stub) runs on three files from
PDC study PDC000504, DIA-NN 1.8.1 and 2.3.0. These are separate from the April audit above and
use their own IDs (`R1`...). Each entry says how sure the finding is and how it was observed:
**real run**, **stub run**, **direct tool test** (the tool run by hand in the workflow's
container), or **by reading**.

### Where the fixes from that work are

All of them are on `main` as of 2026-11-27. What was fixed, so that a regression is recognizable:

- **DIA-NN 1.8.1 could not build the Skyline library** (`BLIB_BUILD_LIBRARY` only handled the
  2.x file names). Fixed in "Build the Skyline library from DIA-NN 1.8.x output again".
- **`skyline.document_name = 'results'` failed in `SKYLINE_MERGE_RESULTS`** (the merged ZIP had
  the same path as the staged `results.sky.zip`), and **a local `skyline.template_file` named
  `results.sky.zip` was deleted from the user's own directory** by `SKYLINE_ADD_LIB` while the
  run reported success. Fixed in "Stage the Skyline documents so a step cannot overwrite its
  own input".
- **A document or batch name ending in `_`, with annotation or minimize on, ended in
  "Join mismatch"** after every Skyline step had finished; the same for a PDC study whose
  normalized name ends in `_`. Fixed in "Match final Skyline documents to batches by predicted
  file name".
- **A document name with a space failed in `SKYLINE_ADD_LIB`** on the DIA-NN path; a batch name
  with a space failed in `GENERATE_QC_QMD`; any published file name with a space (for example
  a `.skyr` report called `Replicate Summary`) aborted `combine_file_hashes`. Nothing validated
  `skyline.document_name`. Fixed in "Support spaces in the Skyline document name and reject
  unusable names", which also adds the startup checks.

- **Input files with a space in their name failed (R2).** Real runs showed which ones: the
  FASTA and `skyline.fasta` and the Skyline template (`SKYLINE_ADD_LIB`), the replicate
  metadata (`SKYLINE_ANNOTATE_DOCUMENT`), a `.blib` or `.dlib` library that has to be converted
  (`ENCYCLOPEDIA_BLIB_TO_DLIB`, `ENCYCLOPEDIA_DLIB_TO_TSV`), MS files on the EncyclopeDIA path
  (`ENCYCLOPEDIA_CREATE_ELIB`) and the Cascadia path (`CASCADIA_SEARCH`), Bruker `.d.zip`
  archives (`UNZIP_DIRECTORY`), the Carafe FASTA and peptide results file (`CARAFE`), and any Panorama file whose URL
  has an escaped or literal space in its last segment. MS files on the DIA-NN path, `.skyr`
  files, the PDC inputs and a library used without conversion already worked. Fixed in
  "Support spaces in input file names"; the rules are in SPECIFICATION.md under "Input File
  Names", and `test-resources/check-script-quoting.py` enforces the two that stub runs cannot
  see. A run started before that commit and resumed after it repeats the steps whose script
  changed and what follows them: library conversion (and then the search) when the library
  is a `.blib` or `.dlib`, the EncyclopeDIA combine step, the Cascadia search, Carafe, and
  the Skyline steps. The DIA-NN and EncyclopeDIA searches of other runs stay cached.

These sit on top of the directory hand-off between Skyline steps (PR #47, landed on `main` the
same day as "Pass the merged Skyline document directly to annotation" and "Hand the Skyline
document between steps as a pruned directory"). The hand-off was compared against the previous
ZIP-at-every-step code with real runs; see "Not tested" below for what it has not been run on.

### Open issues (not fixed anywhere)

**R1. The rendered QC report is never published.** High confidence (real runs, on `main` too).
`RENDER_QC_REPORT` in `modules/qc_report.nf` uses a closure as its `publishDir` `pattern`
(`pattern: { name -> name.endsWith(".${report_format}") }`). A closure is not a glob and
matches nothing, so `<name>_qc_report.html` stays in the task directory while
`file_checksums.tsv` lists it under `qc_report/`. Since `acbb95f` (2026-04-29), which replaced
`"*.${report_format}"`. Reproduce: any real run with `qc_report.skip = false`, then look for an
`.html` in `results/.../qc_report/`. The cause is from reading; only the symptom was observed.

**R2. Input file names with spaces fail.** Fixed; see the list above. Two things were left:
- `pdc.gene_level_data` still cannot have a space in its file name (by reading:
  `EXPORT_GENE_REPORTS` writes the path inside single quotes). It is part of the QC reporting
  code, so the script was not touched; `main.nf` rejects such a name at startup instead.
- Only spaces were tested. Other shell metacharacters in an input file name are unchecked.

**R3. `file_checksums.tsv` is incomplete and loosely formatted.** High confidence (real runs).
- It omits the DIA-NN `.blib` and the predicted `.speclib`. Same family as M1 and M2.
- `echo -e $text` in `modules/file_stats.nf` is unquoted, so runs of spaces in a file name
  collapse to one, and every search-file row ends in a trailing space. Quoting the variable
  turns the kept newlines into blank lines, so both ends need changing together.

**R4. A QC report in PDF format fails in the `dia_qc_report:2.7.0` image.** Medium confidence
(direct tool test, not a workflow run). `quarto render ... --to pdf` stops with
`LaTeX Error: File 'tcolorbox.sty' not found`, for any project name. Reproduce with
`qc_report.report_format = ['pdf']`.

**R5. A template that already contains a file named like a staged input makes
`SKYLINE_ADD_LIB` fail at `unzip`.** Medium confidence (shown with `unzip` on a constructed
ZIP, not in a workflow run). Typical case: the template is a document from an earlier run with
the same document name on the DIA-NN path, so it contains `<document_name>_diann_lib.blib`,
which is also the staged library's name. `unzip` prompts to replace it, reads EOF and exits 1.
Unzipping the template into its own directory would avoid it.

**R6. Names the startup check does not cover.** `validate_document_name` and
`validate_batch_names_for_documents` (`modules/utils.nf`) reject only shapes shown to fail. Left unchecked and documented as unsafe:
- Non-ASCII letters fail in Skyline under Docker (direct tool test with `é ü`).
- `[ ]` and `{ }`: Nextflow reads an output file name as a glob, so `a[b]` and `a{b,c}` end in
  "Missing output file(s)" while `a[b` and `a{b}` work (toy stub test).
- A batch name starting with `-` is accepted; by reading it fails once QC or Skyline reports
  are made, because the report files are named `<batch>_...` and are passed to command-line
  tools.
- A trailing space in the document name is accepted and was only tested against `SkylineCmd`
  directly, not through the workflow.

**R7. PDC naming.** Cosmetic unless noted.
- On single-document PDC runs only the Skyline document is named after the study. The library
  and QC project stay `final` (`final_diann_lib.blib`, `final_qc_report.qmd`), because
  `modules/diann.nf` `get_blib_name()` and `subworkflows/generate_qc_report.nf` read
  `params.skyline.document_name` directly. High confidence (real run).
- `PDC_client studyName --normalize` (upstream tool, image `pdc_client:2.3.3`) treats digits as
  separators: `CPTAC Deep Proteomics 2D-DIA` becomes `CPTAC_Deep_Proteomics_D_DIA`. It is also
  why some study names end in `_` (4 of the 277 public studies on 2026-11-26).

**R8. `DIANN_SEARCH` and `diann_search_serial` are unreachable.** By reading.
`subworkflows/diann/main.nf` includes only `diann_search_parallel`; the Carafe workflow aliases
`CARAFE_DIANN_SEARCH` as `DIANN_SEARCH`. The process is maintained but never runs.

**R9. Docs and help text drift.** By reading.
- `docs/source/results.rst` calls the QC files `qc_report.qmd` and `qc_report.html`; they are
  `<document_name>_qc_report.*`, or `<batch>_qc_report.*` in batch mode.
- In the config GUI repo, the help for `images.diann` (`src/params/paramMetadata.ts`) links to
  `nf-carafe-ai-ms.readthedocs.io`, apparently another project's docs.
- DIA-NN 1.9.2 works (one real run; it writes the 2.x file names) but is mentioned nowhere.

**R10. Misleading output.** Cosmetic.
- After a join failure in `workflows/skyline.nf`, PDC runs print a second
  `Join mismatch ... key=skyline_annotations.csv` from `combine_file_hashes` being cut short
  (stub runs).
- `UPLOAD_FILE` echoed `"Uploading ${file_to_upload} ..."`, a path in quotes, so the log showed
  `my\ doc.sky.zip`. Fixed with R2 (it now prints the plain file name).

### Found on 2026-11-27 while fixing R2 (not fixed)

Same conventions as above. All of these are on `main` and none is caused by the R2 fix. Each
entry says what happens, where, how to reproduce it and, where one is obvious, a way to fix
it. None of the suggested fixes has been tried.

Before changing a process script for any of them, read "Changing a process script" under
"Input File Names" in SPECIFICATION.md: an edit inside a `script:` block makes every resumed
run repeat that step and what follows it.

**R11. `result_dir` and `report_dir` set in a config file are mostly ignored.** High
confidence (stub run, and `nextflow config`). `conf/output_directories.config` builds every
per-tool directory from `params.result_dir` while `nextflow.config` is being read, before the
user's `-c` file is applied, and the report/timeline/trace paths are built from
`params.report_dir` the same way. With `params.result_dir = 'custom out/run 1'` in the user's
config only `nextflow_run_details.txt` and `file_checksums.tsv` (and `pdc/`, `carafe/`) go
there; `diann/`, `skyline/`, `qc_report/` and the reports still go to `results/nf-skyline-dia-ms`
and `reports/nf-skyline-dia-ms`, and `file_checksums.tsv` records the default paths. Given on
the command line (`--result_dir`) both work, including a path with spaces. Reproduce: any
stub config plus a `-c` file that sets `params.result_dir`. Neither parameter is in
`docs/source/`. A fix has to build the directories after all config files are read, for
example in `main.nf`, or the docs have to say to use the command line.

**R12. The Cascadia steps write empty log files.** High confidence (real run).
`CASCADIA_SEARCH`, `CASCADIA_FIX_SCAN_NUMBERS` and `CASCADIA_CREATE_FASTA` in
`modules/cascadia.nf` put the `> >(tee ...) 2> >(tee ...)` redirection on its own line with no
`\` before it, so it is a separate, empty command. `<name>.stdout`, `<name>.stderr`,
`fix_scan_numbers.std*` and `create_fasta.std*` are published with 0 bytes. Reproduce: any real
Cascadia run, then look at the sizes in `<result_dir>/cascadia/`. Fix: end the command line
before each redirection with ` \`.

**R13. `CASCADIA_SEARCH` publishes a copy of every input mzML.** High confidence (real run).
Its `ssl` output is `tuple(path(ms_file), path("<name>.ssl"))`, and the process publishes all
of its outputs, so each mzML is copied into `<result_dir>/cascadia/`. Reproduce: any real
Cascadia run. Fix: give the `publishDir` a `pattern` that leaves the mzML out.

**R14. A Skyline template that already contains results cannot be used.** High confidence
(real run with a document downloaded from Panorama Public). Such a template has its own
`.skyd`, so every `SKYLINE_IMPORT_MS_FILE` task emits two `.skyd` files, the grouped channel
holds lists of lists, and `SKYLINE_MERGE_RESULTS` stops with
`Not a valid path value type: java.util.ArrayList`. Nothing says the template is the cause.
Reproduce: set `skyline.template_file` to any `.sky.zip` that has replicates imported (the one
used was `Calibration Curves_FinalQuantPep_2021-10-08_11-39-17.sky.zip`, see the notes
below). Possible fixes: have `SKYLINE_ADD_LIB` fail with a clear message when the template
ZIP contains a `.skyd`, or have the import step emit only `<ms file>.skyd`.

**R15. With `-resume`, a renamed FASTA keeps its old name on the predicted library.** High
confidence (real run). `DIANN_BUILD_LIB` uses `cache 'deep'`, which hashes file content and
not the file name, so after renaming the FASTA the cached task is reused and
`<old name>.predicted.speclib` is published. Cosmetic, but it also means a resumed run does
not re-test that step: move its work directory aside first. Reproduce: run, copy the FASTA
under another name, point `fasta` at the copy, and run again with `-resume`.

**R16. EncyclopeDIA's converters exit 0 when they fail.** High confidence (real runs).
`ENCYCLOPEDIA_DLIB_TO_TSV` and the `-libexport` step of `ENCYCLOPEDIA_CREATE_ELIB` print a Java
exception (or find no input files) and still return 0, so the failure is reported only as
"Missing output file(s)" with the cause in the task log. Seen before the R2 fix with a
library or MS file that had a space in its name; any input the converter cannot read will do
the same. Fix: `test -s` the expected output at the end of each script, as the Skyline steps
do.

**R17. The Panorama download steps keep their logs in the file cache.** High confidence
(real run). `PANORAMA_GET_MS_FILE` and `PANORAMA_PUBLIC_GET_MS_FILE` have a `storeDir`, which
stores every output, so `panorama-get-<file>.stdout` and `.stderr` sit in
`panorama_cache_directory` next to the MS files. Reproduce: download any MS file from
Panorama and list the cache directory.

**R18. A failed Cascadia search is followed by a second, unrelated error.** Cosmetic (real
run). After `CASCADIA_SEARCH` fails Nextflow also prints
`A DataflowVariable can only be assigned once`. Same family as R10. Reproduce: make
`CASCADIA_SEARCH` fail, for example with a truncated mzML.

**R19. Every run without `skyline.template_file` depends on a download from GitHub.** High
confidence (real and stub runs). The default template is fetched from
`https://github.com/mriffle/nf-skyline-dia-ms/raw/main/resources/template.sky.zip` when
`SKYLINE_ADD_LIB` is staged, which is after the search has finished. On 2026-11-27 that URL
returned 504 for about 15 minutes (the same file on `raw.githubusercontent.com` was served
normally) and every real run and every stub config that relies on the default failed there
with `Can't stage file ... Unable to access path`. The template is in the repository
(`resources/template.sky.zip`), so it could be taken from `projectDir` instead. Changing
`default_skyline_template_file` is a default change: schema, docs and the config GUI follow.

**R20. A startup error can be replaced by a spurious "No spectra files matched".** Medium
confidence (seen once, in CI run 46060261061 for commit `01d74ac`, Nextflow 26.04.0; the cause
is from reading). `test-batch-name-document-collision.config` must fail with
`Batch names 'Plate1' and 'Plate1_' would produce the same Skyline document name`, raised
while the workflow is being built (`check_final_skyline_doc_names`). In that run the only
error printed was `No spectra files matched the glob/regex` for both batches, although both
directories hold `.raw` files, and the negative test failed for lack of the expected text.
The likely cause: when construction fails, the channels are closed empty, the validation
barrier in `subworkflows/get_ms_files.nf` (`validation_ch`) then sees no batches at all and
raises its own error, and that one can win the race to the console. It passed in the same
job on 24.10.5 and 25.10.4, in every earlier CI run, and in nine local runs of the suite, so
it is rare. The user-facing effect is a wrong error message for a bad config; the CI effect
is an occasional red negative test that passes when re-run. Same family as R10. A fix would
be for the barrier to stay silent when it receives nothing (an empty list cannot be told
from "no batch matched", so it needs a sentinel), or to do the construction-time checks
before `get_ms_files` is called.

Also seen in that CI run, and not a defect in the workflow: two jobs failed with
`Error during download of plugin nf-amazon` / `nf-schema` on the runner. Re-run them.

#### Notes for whoever picks these up

How the 2026-11-27 work was tested, so that it does not have to be rediscovered:

- Real runs used three files of PDC study PDC000504 (`pdc.n_raw_files = 3`,
  `msconvert.do_demultiplex = false`), a FASTA made of every fourth human Swiss-Prot entry,
  4 CPUs and 10 GB per task, and DIA-NN 2.3.0 or the default 1.8.1. The same three raw files,
  copied under other names into a local directory, serve as local input.
- EncyclopeDIA needs a library: the `.blib` a DIA-NN run publishes works
  (`spectral_library = '.../final_diann_lib.blib'`).
- Cascadia takes about 44 minutes per full file on an RTX 4090 (`cascadia.use_gpu = true`).
  Two mzML files cut to four minutes of gradient
  (`msconvert ... --filter "scanTime [2400,2640]"`, then `quant_spectra_glob = '*.mzML'`) run
  the whole branch in about ten minutes and still give a small document.
- Carafe runs on CPU in about 15 minutes with one mzML as `carafe.spectra_file`.
- Panorama downloads can be tested without an account. Panorama Public has a file with a
  space in its name, `Calibration Curves_FinalQuantPep_2021-10-08_11-39-17.sky.zip`, in
  `https://panoramaweb.org/_webdav/Panorama%20Public/2021/Nebraska%20U%20FARRP%20-%20Soy%20Quantification%20Method-%20Matrix%20Extension/%40files/`.
  As `carafe.spectra_file` it goes through `PANORAMA_PUBLIC_GET_MS_FILE`. Written with
  `panorama%20public` in lower case it is taken for an authenticated URL and goes through
  `PANORAMA_GET_FILE`; the secret `PANORAMA_API_KEY` can then be Panorama's public key
  (`params.panorama.public.key`). No public MS file with a space in its name was found, so
  the listing step has not been run on one.
- A Bruker `.d.zip` for the extraction step can be made by zipping a directory `<name>.d`
  with any file in it and running with `msconvert_only = true`.
- Run a series of cases in one launch directory with `-resume` and move `results/` away after
  each: only the steps that changed run again. Mind R15, and that the last `-c` file wins.
- A stub run cannot show any of the R2 defects. `test-resources/check-script-quoting.py`
  finds that class of defect without running anything.

### Known before this work, still true

- With default symlink staging, `SKYLINE_MERGE_RESULTS` deletes the import tasks' `.skyd`
  outputs (Skyline removes partial caches after joining), so the imports re-run on every
  `-resume`. `skyline.use_hardlinks = true` is the documented remedy.
- Replicate order in the Skyline document follows import completion order, and the minimized
  library gets a new random ID each run, so two identical runs do not give byte-identical
  documents. Sort Skyline reports before comparing them.
- The merge step leaves a `results.skyd` in its work directory and copies the caches to `/tmp`
  without apparent use.

- The directory hand-off between Skyline steps on AWS Batch (where every input is copied, not
